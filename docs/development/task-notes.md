# 默认 Task Notes：操作经验

新 benchmark 运行默认注入 [`actor_instructions.py`](../../auriga/cortex/context/actor_instructions.py) 中的 `OPERATION_NOTES` 操作经验表，配合自由文本 `task_plan` 使用。经验表供按情境选用，不是需要填写的计划表单；新接口见[统一动作与程序审批](unified-actions.md)。下文概述各版本覆盖的内容；归档恢复始终使用当时保存的正文。

新运行使用 `unified_operation_notes_v7`。启动经验表收敛为通用判断：任务/几何理解、抓持/运输/协作（含指尖/支撑面净空、更深接触区未必更优、横向搬运/折叠前先提离支撑面）、单臂不可达跨臂交接与双臂同步操作、放置/释放、失败后的反证策略（含 `tracking_error` 后结合 `actual_contact_position_m` 与 `approach_shortfall_m` 修正接触高度/接触段而非原高度横移或重复受阻下探），以及并行与全过程预算（含避免子任务间不必要的中间回原点）。选择抓点和支撑时仍考虑预定转腕及交付姿态；初次抬起不能证明转腕后仍保持，重复闭爪也不证明夹力更强。

已提交计划后，默认非超长的 `/responses` 请求不改写对话历史，也不在末尾删改并追加提醒，以保持每次请求都是上一请求的严格前缀延伸（从而复用上游 prompt cache）；仅在上下文超限触发 `/responses/compact` 时，出口才删除输入中已有的 Harness 快照并注入当前完整 plan、attention 和 ledger 快照及短决策边界。完整快照仍只是 assistant 的暂定判断，不升为 developer 指令。现有 `concern/check/when` 继续记录当前问题；任务阶段前提另由可选的 `ledger` 记录 `id/expected/status/basis/next_check`，最多三行，以免计划中发现的边界在后续动作或压缩中消失。

## task-evidence-boundary-v1

evidence ledger 是现有 `task_plan` owner 的一个可选字段，attention 的原语义不变。每个 episode 最多保存 3 个短条目：`status` 只能是 `pending`、`supported`、`contradicted` 或 `unknown`；`basis` 只写当前允许的 RGB、测量状态或 typed receipt 简述，没有依据时写 `unknown`；`next_check` 写下一步要区分的事实。条目 ID 在同一列表内唯一，更新是整表替换，省略保留，`[]` 清空；旧记录缺少 ledger 时读作空表。

CodexSession 在主 actor 的 `/responses/compact` 压缩出口注入当前 ledger 与短的证据边界规则；默认 `/responses` 请求保持原始对话历史不变以维护前缀缓存。规则说明 pending 不是已建立前提，completed motion、preview success 和 closed gripper 不能证明物体结果；重复失败时要改变假设或选能区分原因的动作。ledger 只提醒和保留审计结构，不阻止 `robot_action`/`robot_wait`，也不要求为了填表增加探测 action。完整 observation/action 引用仍留在内部 Store；模型投影不带 hash、evaluator 或内部 source metadata。recovery 专用 tested-candidate ledger 继续由 recovery owner 管理，不与 task ledger 合并。

这一设计针对“计划里发现了问题，但后续动作忘记该前提”的失败机制，同时保留连贯的试探。CPU 回归覆盖 schema、原子更新、旧档兼容、普通 `/responses` 前缀保持、`/responses/compact` 快照投递与重试及辅助线程隔离；这些检查只证明接线和边界，不证明模型会正确填写状态或 native 成功率会提高。

普通执行中 `task_plan` 调用本身保留在对话历史中，仅 `/responses/compact` 压缩时由请求 hook 补齐当前完整快照；recovery v4 的 continuation 用户消息补充恢复专用候选账本、计数和反证规则。真实 HTTP 回归覆盖普通 `/responses` 连续请求的前缀延伸、同一正在执行的 turn 内更新关注项与后续清空后的 `/responses/compact` 投递、重试请求一致性及辅助线程不注入；程序内部没有新模型决策时也不会自动监视关注点。这些软件检查不证明模型会遵守规则或 native 效果改善。

## 统一操作经验表的早期版本

`unified_operation_notes_v5` 在原表中改写四类判断：按公开任务核对对象归属；用固定场景参照区分物体运动与腕相机运动；验证任务要求的放置位置/方向并保留未解决的偏位；计数依据物体事件，失败运动也可能改变物体、完成运动也可能没有产生目标事件。未加入任务专用解法、固定阈值或额外探测阶段。

规划说明同时明确：整体任务理解、对象归属或做法变化时，更新 `plan` 及受影响的 `attention`；只更新 attention 会按契约保留原正文。仍影响任务的未解决问题不能无依据地改成完成，但可以根据新证据、对旧证据的明确重新解释或相关性变化改写/删除，用已有自由文本简短说明依据即可。不强制新增观察、每动作更新、条目不可删除或额外解释字段，同一观察下纠正判断仍被允许。这些提示针对计划正文未随新判断更新、同一观察下前后矛盾以及把接触停滞等同于计数事件的情况，不证明能够纠正模型判断。

状态与投递不会复活旧 revision 缓存或自动丢条目：`TaskPlanning.current` 核对本 episode 与持久化原记录，`decision_context` 读取最新 owner，`CodexSession` 在实际 Responses 请求出口加入当前快照，之后经过共享过滤。attention-only 更新保留正文、显式 `[]` 清空，均与实际工具参数一致；不设语义门禁，也不自动恢复已删除条目。

部分更新的观察依据按字段记录：保存记录、决策快照和自由文本 `read` 分别使用 `plan_observation_id`、`attention_observation_id` 与 `ledger_observation_id`，只刷新显式提交字段的来源；它们表示提交判断时的观察，不证明判断成立。显式 `[]` 记录清空时的观察，`submit` 省略 attention 则清除旧清单及其来源。相同观察下重复提交相同字段返回 `unchanged`，避免无意义的 revision 和上下文副本；在新观察下重复文字仍保留为新的判断来源。旧档没有分字段来源时返回 `null`，不推测历史，也不回写原档。短 ACK 保持不变；跨观察部分更新、旧档兼容、请求快照及实际 HTTP 投递有 CPU 回归。

`unified_operation_notes_v4` 将正文按“适用情境—可见检查—反证后调整”组织通用经验，开局只选当前有关考虑；新的观察、抓持变化、接触失败或过程状态不确定出现时，可以重新选择任何相关经验。没有固定顺序、勾选项或新工具，也不要求每一步重新填写计划或输出冗长推理。

初始计划说明当前场景理解、做法和完成依据；当前问题、判断证据与调整方式、检查时机放在可选 `task_plan.attention` 清单中。主模型在每个 actor 请求收到当前完整版本；局部关注项可单独更新，整体理解变化时同步修订仍适用的内容。清单可按依据重新选择、替换或清空。要重复无效操作模式时，先简短说明原因假设，以及能区分它的观察或策略变化。优先利用正常推进动作的反馈完成检查，缺失证据会影响下一步时才另做探测。计划仍是建议，不绑定工具选择，也不要求逐动作填写。字段语义、请求 hook、原生待办取舍与程序边界见[统一动作接口](unified-actions.md#从理解任务到执行)。

表中补充了同一物体的短抬共动与源位空出、机器人接触参考不等于物体接触、转腕/转手后的物体相对夹爪姿态、释放并撤离后的落点留存，以及无法确认的过程状态和计数。保留双臂并行与流水线、可达性不足时中转、同物体双臂协作、空闲臂腕视角、整臂/持物净空、全过程预算和任务要求的最终回位。坐标与参数约定仍由启动契约和工具说明定义；经验不包含任务专用坐标、隐藏状态、答案或额外成功条件。

版本变化只作用于新运行。测试检查实际启动注入、归档/恢复一致性及自由文本计划可修改而不锁定动作，不能据此声称成功率提高。

`unified_operation_notes_v3` 增加空闲臂辅助观察建议，并保留 v2 的双臂操作建议；这些意图在 v4 中继续保留：

**空闲臂辅助观察。** 当一只机械臂执行操作、另一只空闲时，可以调整空闲臂的腕部相机，从侧面或斜侧面观察物体与操作手指，尤其适用于主视角难以判断相对高度或接触关系的情况。结合这一补充视角的最新图像与操作臂的反馈，判断高度、间隙和接触情况，为下一步动作提供依据。观察臂应避开操作区域，并将调整视角所需的运动成本计入预算。

**双臂并行与流水线调度。** 鼓励根据实际情况让双臂并行推进，但不强制同时动作。当一臂处理主要工作或困难操作时，另一只空闲臂可以先完成容易、独立的子任务，形成流水线，充分利用同一段环境时间步，避免因一臂长期处理难题而让另一臂持续闲置。两个简单任务，或一个简单、一个困难的任务，通常适合考虑并行；两个困难任务也可以并行，只要它们的路线、资源和观察需求互不冲突。若存在依赖、共享空间冲突或需要先观察再决策，应安排顺序。判断依据是当前场景中的可达性、双臂及持物的完整扫掠空间和反馈需求，而非仅凭任务难度决定并行或串行。

**可达性不足时的跨臂中转。** 当主要工作臂够不到某个物体，而另一臂可以够到时，可以由另一臂将物体移到工作臂可操作的区域。例如，主要使用左臂操作，但物体距离左臂较远时，可由右臂先搬到双方可达的稳定桌面位置，再由左臂接手。桌面或其他稳定支撑面中转主要用于这类跨臂搬运和交接；仍需结合可达性、支撑稳定性、净空和整体成本选择合适方式。

**单臂操作困难时的双臂协作。** 当一个物体难以由单个机械臂、单个夹爪完成操作时，可以考虑让另一臂协助。例如，将异形物体摆正时，一臂可以提供支撑或稳定，另一臂配合转动、调整姿态。这类协作可以借助桌面或其他稳定支撑面，也可以由双臂直接在空中配合；应根据当前物体几何、抓持稳定性、可达性、净空和操作目标判断，两种方式没有预设偏好。协作不必包含物体从一臂转交给另一臂；操作中仍须确认支撑、抓持和最终姿态，并遵守本次运行明确设置的许可限制。

跨臂中转保留原有 `airborne_handoff=true, handoff_preference="surface"` 默认策略：适用时推荐稳定支撑面，不强制落桌。该交接偏好不决定困难物体的双臂协作方式；启动政策中也明确区分两者。历史正文、配置及恢复记录保留。这些是规划建议，已验证启动注入和归档行为，不据此声称成功率或步数收益。下文的 v16 操作规划说明属于此前版本。

## 此前的 `operation-notes-*` 正文

[`auriga/cortex/context/task_notes.py`](../../auriga/cortex/context/task_notes.py) 保留统一操作经验表之前的版本化正文：`DEFAULT_TASK_NOTES` 为 `operation-notes-v16`，`PREVIOUS_DEFAULT_TASK_NOTES` 为 v14，`LEGACY_DEFAULT_TASK_NOTES` 为 v11。`resolve_task_notes` 仍按 `features.manipulation_protocol`、`features.task_scheduling` 与 `features.operation_candidates` 选择其中一份并记录配置（`manipulation_protocol=false` 选 v11；`task_scheduling` 与 `operation_candidates` 均关闭时选 v14；否则选 v16），新运行随后由 `actor_instructions.task_notes` 把默认正文替换为当前操作经验表。这些正文只使用部署时可获得的信息，不包含场景答案、历史目标坐标、物体隐藏尺寸、评分阈值或任务专属步骤。

v16 在调度上补充：比较改变失败机制的恢复与独立任务；已持物的机械臂考虑先交付，路线独立时与另一臂的恢复/准备重叠；不等长路线可使用independent推进，共享通道先让行。换目标前检查退出及下一次进入是否破坏已放物体和支撑；扰动后重估路线，不为未经确认的姿态要求破坏已验证成果。空闲臂不必阶段归位。以上仍是建议，不推断持物/完成状态、不自动移动或移除依赖。

当前默认四项为 `task_scheduling=true, operation_candidates=false, preview_intent=false, recovery_evidence=true`。完整操作候选停止默认使用，不再继续扩展；原接口保留为显式opt-in及历史回放兼容。预览用途区分关闭，原 `include_trajectory`、成本预览、采样关节、轨迹图和动作后automatic反馈保留。恢复证据策略保留。变更只作用于新建且未显式覆盖的配置，不改已冻结实验或归档配置。

v15 补充两项可分别消融的建议：

- **调度**：任务列举次序和plan数组次序不构成执行依赖，依赖应来自明确要求、物理前提或必要观察。允许在阶段写可选 `dependency_reason`；旧计划缺少该字段仍接受，只返回一次简短review建议，不自动删除依赖。抓取失败、物体移位或反复恢复后，应重新比较独立子任务、两臂持物占用和整段成本，避免另一臂已拿到物体却一直空等。可选 `task_plan.scheduling` 只记录重要选择，不要求每动作更新，也不引入单臂优先。
- **完整操作候选**：困难或修订操作比较接近、接触、运输、放置、分离、撤离、核验及任务确需的归位，不能只因为下一个接近点便宜就启动。结合物体接触截面、物体相对夹持方向、手指接触区和完整扫掠空间；开爪不等于分离，高路线不可达不能简单把同一路线降低后横扫。可选 `operation_context.candidate` 保存当前观察绑定的简短阶段估计，不自动拼接执行。未知阶段保持未知，不强制编造几何或预算。

这两项针对长期串行等待、恢复占用持物臂、成功末端动作破坏已放结构等失败机制，是机制性建议，不据此声称成功率提高，也不证明某个固定顺序或姿态对所有任务有效。

运行时失败回包可复用 `scheduling_failure_advisory(receipt, plan_record, task_scheduling=...)`（位于 `legacy_task_planning.py`）：仅failed/rejected提供一句重选建议和最多三个无显式依赖的计划阶段引用；成功、未知状态或关闭时不提供。引用标记为待重新评估，绝不推断阶段已就绪、仍未完成或某臂实际持物。建议提醒查看当前RGB中的占手情况，比较改变机制的恢复、交付已拿物体、使用已观察的稳定支撑或独立工作，同时检查共享通道、退出与下一次进入对已放物体的影响；不读取物体真值，不执行放手、移动或预算扣减。

v14 与 `actor_task_plan_v7` 共用抓取和完整路线提示。抓取方向先相对物体的形状、支撑姿态和可夹截面判断，优先比较合适的斜向候选；抓稳与净空相当时保留从上方接近、向上提离的偏好。明确警惕世界水平侧抓/转向造成手指、掌部、腕部和前臂横扫，不固定倾角、不改变工具坐标约定。选择手臂时比较全程可达性和遮挡，允许对侧/对角操作；静止的另一臂也可能挡路，进入共享通道前应让开，空间独立时仍保持双臂并行。

放置、分离、退出、转向一起规划：在可达、上方净空和预算允许时优先用足够高的通道越过障碍，完成分离后提离再大幅横退/转向。不是机械臂绝对最高点，也不是从高处松爪投下；仍慢降到合适支撑/释放位。箱壁、箱沿与纸板翻盖均有体积，需同时考虑持物底部、夹爪与整臂退出。容器难以进入时，可根据任务约束和现有内容考虑先调位置/方向。实质性扰动后重新估计场景和整条路线，不仅改落点。以上是条件式规划建议，未新增物理动作或硬门槛。

v13 加入有条件的垂直优先策略，并与 `actor_task_plan_v6` 共用同一段提示：在夹持稳定、夹指有效接触深度足够、机械臂可达且上方净空允许时，优先从上向下垂直夹取，先垂直提离邻近物体；搬运时在稳定和净空允许的条件下保持适宜的垂直夹持姿态，并考虑整物高度和放置要求。相比水平侧抓，这通常减少穿过邻物的横向扫掠，但不是免碰撞保证。物体形状、重心/平衡、滑移风险、接触部位、障碍和最终放置需综合判断，抓稳优先；水平夹取或有支撑重抓更合适时仍应采用，不为追求垂直而在拥挤区强行转动已抓稳的物体。该偏好不是工具硬门槛，不改变双臂并行、速度、夹爪接触区域或交接开关。旧归档及protocol关闭时的v11/v4说明保持原样。

v12 配合当时的操作上下文与模板 v3（模板现已删除）把近期抓取、放置和平面中转决策落实为可检查参数：当前物体标签、actor状态、公开观测来源和不确定性只写一份；接触区域由模板实际转发到 `move/lift`，放置时记录物体静置位姿、底部与手指关系、沿/边界、释放落差和撤退路线。几何可用短文字或 `unknown`，不要求捏造精确数值。中转同时考虑支撑落点、给手退出和接手进入通道，并说明可并行的其他工作；接手引用释放后更晚的给手清离观察。给手清离后即可进行接收，回home可以稍后或在空间独立时并行。

完成释放模板只产生 `released_unverified` 与观察id，留存需actor引用RGB分离和稳定落点证据。来源白名单为RGB、proprioception、calibration、公开URDF；物体估计由actor从RGB推断，不读取模拟器物体坐标、隐藏评分或接触真值。字段/观测id校验只是声明一致性，绝不证明接触或物理支撑。协议不新增模型验证调用或自动等待；确需观察落稳时，用现有有界 `robot_wait` 显式计入native预算。

`manipulation_protocol=false` 同时选择v11 notes、v4 task plan说明/schema与v2模板行为，供同源码消融；`handoff_policy`独立选择策略，旧两种bool策略仍可恢复。阶段未知时仍可只写观察目标，无须为整个任务预填几何。普通transit、现有双臂/independent/queue接口不增加接触表单，也不新增surface Skill。CPU测试验证参数落实、观察引用和状态边界；不能仅由启用开关声称性能收益。

v11 补充：接近受阻时同时调整物体截面、夹指深入方向和支撑姿态，不能仅换成 `finger_middle` 后继续顶；区分 held、released-unverified 与 visibly retained，在恢复仍可行时完成落点确认，不拖到最终归位后；在昂贵姿态变化或反复失败前按实际速度使用成本预览，预留所有未完成物体、验证与必要归位的预算。结合现场先易后难、不偏好单臂、保留双臂并行、避免无必要阶段归位、arm/jaw slow 均为 0.8 的要求不变。

交接许可与偏好分别由 `features.airborne_handoff`、`features.handoff_preference` 控制，并作为运行政策注入 actor developer instructions、保存在启动配置与 manifest 的 `handoff_policy`。新默认是 `true + surface`（`prefer_surface`）：模型根据当前几何、抓稳、可达性、双臂净空和全任务成本自主选择空中或支撑面交接，推荐适用的稳定物理平面，不强制落桌。`true + airborne`（`prefer_airborne`）恢复旧空中优先策略；`false + surface`（`surface_only`）恢复旧硬禁止策略。显式旧bool且未给偏好时，true映射airborne、false映射surface，归档恢复同样保留其原有行为。

支持面交接仍需检查放下后的实际支撑、给手清离及接手后短抬留持；空中交接仍在给手保持支撑时完成接收臂接近／闭爪，返回新观察，确认接收支撑后才能另行释放给手。空中接手模板存在peer时仍要求paired。三种策略都使用现有双臂／队列工具，不关闭同时动作或independent推进。策略不依赖可选默认notes是否开启；不把新默认写回旧实验。底层pose工具不推断物体身份或真实支撑，专用空中接收模板仅在硬禁止模式下拒绝。

这些是从既有成功、失败与恢复轨迹归纳的操作提醒。提示要求按当前证据选择相关检查，不要求每步执行整份清单，也不添加新的任务完成条件。

`operation-notes-v2` 将早期实验中可复用的几何经验并入现有条目：第 1 条补充公开的 ARX X5 名义最大内开口 88.8 mm、开合轴约定、局部截面与双指居中，并明确抓取高度/深度要让接触部位落在有效夹持面内；空提后按实际偏差调整，不设固定降低量或旋转角。短抬与搬运保持、周围物体间隙、观察选择及工具中心约定已分别覆盖于第 3、5、7、8 条。

`operation-notes-v3` 在第 4 条补充容器内放置提醒：松爪前将物体本身对准容器开口中心，留出与边缘的间隙，针对放入容器时松爪靠近边沿导致物体弹出的现象。不设置固定坐标或间隙数值。

`operation-notes-v4` 扩充第 1–4 条，并配合移动速度接口：异形或难抓物体比较垂直顶抓与水平侧抓，必要时先在有支撑的状态摆正再重新抓取；无障碍搬运可正常或加快，接触、抓取接近、初始提起和放置要减速；容器放置以可用内部中心为目标，并结合桶沿／壁高、持物姿态、物体底部相对手指的高度与整物净空规划三维路线。慢速松爪单独控制，不能由慢速移臂代替。不加入固定场景坐标、抓取角度或释放高度。

`operation-notes-v5` 保留 v4 的四项操作要求，将速度选择提示改为优先固定档位：机械臂使用 `speed_preset`，夹爪独立使用 `gripper_speed_preset`；需要精调时仍可使用对应的数字倍率，同一控制对象的档位与数字参数互斥。普通空旷移动可以省略速度选择、使用本运行公布的默认值；接触前明确选择 `slow`。显式 `normal` 的含义固定，不随本运行默认移动倍率提高而变化。

`operation-notes-v6` 将内容压缩整合为 10 条：在依赖关系允许时先易后难；能单臂完成则优先单臂，单臂距离不足或操作困难才考虑双臂／交接；阶段结束若不妨碍下一阶段与有用视角，不必回 home 或做大幅空手转姿，但任务明确要求的最终归位仍须完成。跟踪残差后依据实测状态调整接近，避免未建立抓取对位就闭合；搬运同时考虑整物和整臂的转动扫掠，不能只看末端终点。保留容器中心、沿高与持物底部的三维净空、顶抓／侧抓及支撑状态摆正、优先复用已返回视图和裁剪等要求。

v6 同时纠正 v5 的旧接口说明：`waypoint_speed_presets` 或 `waypoint_speed_scales` 可分别选择每个 incoming 段的速度，顺序是途经点再到最终目标；`null` 继承顶层选择，顶层省略才继承运行默认。没有列表时才整请求继承同一速度。空旷接近／搬运与短接触段分速，需要中间新观察或决策时仍分请求。当前 arm 和 jaw 的 `slow` 均为 **0.8**，此次 notes 更新不修改档位数值；档位映射、范围和完整执行语义由工具帮助与[运动速度接口](motion-speed.md)维护，运行默认见[配置说明](configuration.md)。

v6 中先易后难、单臂优先和避免无必要阶段归位是规划偏好；跟踪后闭爪扰物、长空手转腕、持物扫到邻物和同请求全慢耗步是从实际运行中观察到的反例。它们不能证明 v6 提示必然提高成功率。历史会话及冻结实验保留原 notes，旧 slow=0.6 运行也不回写成 0.8。

`operation-notes-v7` 删除单臂优先及“单臂困难后才用双臂”的限制。任务顺序结合依赖、当前机械臂与物体姿态、可达性、遮挡／净空，以及后续移动或恢复成本规划；在有利于整体推进时优先处理容易完成的子任务，但清除障碍、建立前置条件可以优先，场景变化后重新评估顺序。其余条目保留，包括阶段结束不必无故归位。只影响启用默认 notes 的新 episode，不回写 v6 实验。

`operation-notes-v8` 补充夹持接触位置选择：不必固定用爪尖，可根据物体形状、两侧接触面、估计重心与抓取稳定性，选择爪尖或手指内侧夹持面的中部，并相应调整伸入深度。更深夹持须给掌部、手指与支撑面／邻近物体留出净空，不默认越深越稳。通过调整抓取位姿选择接触深度，`robot_move_grasp`（已删除，现为 `robot_action` 移动阶段的 `grasp_position_m`）的标定夹持面中心目标约定保持不变。不固定伸入距离或改变工具标定；历史实验提示不回写。

`operation-notes-v9` 将物体上的抓取截面与手指上的接触截面分开表达。旧 `grasp_position_m` 默认参考是末端 15 mm 平面夹持区的中心，不能把它理解成整根手指中部；可通过 `contact_region` 或互斥的 `contact_depth_m` 显式选区，由工具换算，不要求模型再手工叠加偏移。较深的 `finger_middle` 位于内侧斜面，仍须考虑掌部、指尖、支撑面和邻物净空，不能默认越深越稳。接近跟踪失败后，结合所选参考点的终态实测反馈与 RGB 决定修正或采用其他可行抓法，不能将请求更深当成实际已下探。机械臂和夹爪的 slow 仍均为 0.8。v9 针对两类不同问题：目标深度选择不当导致夹空，以及请求下探但实测参考点仍高于目标就闭爪。

`operation-notes-v10` 将正文压缩为七组决策提醒，把接口参数、互斥规则与坐标细节移至工具帮助。保留结合现场先易后难、无单臂优先、无必要中途归位、物体截面与手指接触截面分别选择、机械臂及夹爪 slow 均为 0.8。新增完整的抓取到放置／归位成本、独立工作与配对到达／观察依赖的区别，以及总预算未知时不得假定剩余量。小步测量修正用于局部恢复，不能代替普通搬运路线。成功搬运／交接的步数成本与失败恢复同样关键；多次双臂调用不等于持续的同时运动。

七组分别是：全操作成本与顺序；依赖及并行机会；物体与手指接触选择；分段速度与抓稳；整物放置；基于实测恢复；净空、阶段姿态及观察。`task_plan` 的可选阶段 `id/arms/depends_on/observation_gate` 只保存可修订的计划意图，图引用与环检查不增加强制动作门槛；数组次序不隐式建立依赖。

## 默认启用、追加与关闭

- 不传任何 notes 参数：新 benchmark 自动带默认操作经验。
- `--task-notes '...' --task-notes-source '...'`：在默认经验后追加公开说明，不替换默认正文；两个自定义字段须同时非空，自定义正文最多 8000 字符。默认正文不占此自定义限额。
- `--no-default-task-notes`：只关闭默认操作经验；显式传入的自定义说明仍保留。关闭且不传自定义说明时，不注入 Task Notes。
- 队列 case 可写 `"default_task_notes": false`；省略则使用 gateway 默认值。`true` 可显式启用。
- 普通开发 smoke 不自动注入；`--resume` / `--replay` 沿用归档内容，不用当前版本补写旧运行。旧 manifest 缺少配置字段时按未启用默认经验解释。
- 新建 episode 的 OOM 重试仍执行其冻结源码和参数。历史 argv 若不含 notes 开关，却在更新后的可变 checkout 中重跑，会继承新默认，不能称相同提示条件；重现实验应使用原冻结源码，或在新配置中显式关闭默认经验并传入原有公开说明。

例：在现有 case 中增加以下字段，可以保留自定义公开说明并关闭默认经验：

```json
{
  "default_task_notes": false,
  "task_notes": "Additional public operation or task instruction.",
  "task_notes_source": "public-document-or-experiment-protocol"
}
```

gateway 在开局拼接一次，再发送给同一 Astra 会话。初始化顺序为完整 `robot_information` 资料、既有 Harness developer instructions、用户任务、任务正文末尾的 Task Notes。公开任务规则、当前预算及可选初始完成提醒均位于 notes 之前；默认经验和自定义说明在 notes 内的顺序不变。

`task_notes_source` 仅作为归档标签保存，不发送给模型，也不触发联网或文件读取。现场新信息仍来自观察及工具反馈；Astra 不会自动改写默认 notes。机器人资料的独立读取与恢复行为见[统一机器人资料接口](robot-information.md)。

实际生效的 `task_notes`、`task_notes_source` 和 `task_notes_config` 同时写入初始 `configuration/task_prompt-<digest>` 记录及 `manifest.json`。配置记录默认开关、默认版本、自定义原文及来源；`source_sha256` 与源码归档包括 `task_notes.py`。离线 benchmark report 直接输出归档配置，不从当前常量重建旧提示。

独立的 `completion_guidance` 默认使用 `hook`：仅在当前双臂测量位姿超出初始归位容差时发送明确回位提醒，已经归位或证据不足时使用原来的通用续接。初始 prompt 的归位提醒默认不注入，可用 `both` 显式开启；详见[配置说明](configuration.md)。操作 notes 中的“回位”只说明执行这类动作时的位姿与路线问题，不要求所有任务新增回位步骤。

## v9 及之前的十条编号

下表保留 v9 及之前的十条编号以便追溯；v10 按上文七组重排，没有将旧编号或全部接口细节重复注入 actor。

| 条目 | 给 Astra 的操作经验 |
|---|---|
| 1. 顺序与抓取选择 | 按依赖、当前姿态、可达性、遮挡／净空及后续成本安排顺序；适合时先做容易的子任务，清障或前置条件可以优先，场景变化后重新评估。不规定单臂优先。按公开夹爪开口与开合轴选择结实局部截面并双指居中；依据形状、接触面、估计重心与稳定性显式选择末端平面、指中或爪尖参考，区分物体截面与手指截面；工具负责偏移换算，保留掌部、指尖与周围净空。异形物比较顶抓／侧抓，必要时有支撑地摆正再抓。空提后按实际偏差调整，不自动固定旋转或降低。 |
| 2. 夹爪状态 | 区分目标命令、实际状态和物体结果；完成动作与闭爪都不是保持证明。部分执行后检查夹爪阶段；接触闭合和放置开爪独立选 slow，移臂减速不替代夹爪减速。 |
| 3. 分段速度、抬升与交接 | 用 waypoint_speed_presets/scales 区分快的空旷接近／搬运和短慢接触；无列表才同速，需要中间决策时分请求。按图确认短抬及转向后的保持；交接前确认接收手实际支撑。 |
| 4. 放置与释放 | 以容器可用内部中心为目标，检查沿高、壁高、持物姿态、底部高度及整形状净空；越沿后慢降慢放，不能只看二维投影。确认分离和落点，遮挡或从画面消失不代表留在容器内；按证据区分未开爪、挂住和遮挡。 |
| 5. 扫掠净空与保护已放物 | 为整物、两臂、开爪和已放物保留整条运动路径的净空，特别是转动扫掠。风险接近后检查拖带／倾倒；目标或支撑被推移后更新后续目标，只修正观察到的问题。 |
| 6. 跟踪与规划失败恢复 | 读内层回执及实测状态；跟踪误差后先按残差修正接近并确认抓取对位，不因目标命令看起来正确就闭爪。拒绝或无进展时停程序循环；不可行目标同时调整位置和姿态，避免无变化重试。 |
| 7. 观察选择与位移核验 | 优先动作已返回视图；针对遮挡／冲突选择腕部、头部、裁剪或必要的改变视角动作。按固定背景和物体特征判断位移，不仅看 EE；不为重复静态画面花动作。 |
| 8. 阶段衔接与最终归位 | 保留位姿和 frame/TCP；阶段末当前姿态不妨碍下阶段或视角时无需回 home 或大幅空手转姿，需要时按实际状态选最少必要移动。任务明确要求的最终归位仍须完成和核验。 |
| 9. 观察动态过程 | 确有等待外部运动/演示/稳定的需要时，使用可用的仿真推进等待工具并看时序反馈。墙钟等待和重复静态读取不推进暂停世界。 |
| 10. 局部策略委派 | 工具可用且决定委派时，明确当前局部意图、有界执行后检查双臂与夹爪；文字指定手臂/距离不是硬约束，短前缀限制时长而不保证位移。 |

## 后续维护与验证

不纳入固定 yaw/高度/步数、任务物体顺序、隐藏评分阈值、自动松爪门槛、强制每步多视角检查或“失败就一定只差回位”等规则；操作经验听起来合理不等于有对照收益。

1. 新经验先记录触发条件、实际动作/观察证据、反例与适用范围，再压缩成操作级建议。
2. 修改当前操作经验表（`actor_instructions.py` 的 `OPERATION_NOTES`）时，同步递增 `task_notes()` 写入的版本与来源标签（当前为 `unified_operation_notes_v7`），并更新本文的版本说明；`task_notes.py` 中的 `operation-notes-*` 常量保留历史版本正文。保持自定义说明追加语义。
3. 新 episode 才使用新版本；已有会话、运行清单、冻结实验和历史报告不回写。
