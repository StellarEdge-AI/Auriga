# Formal Observation and Diagnostic Information Boundary

New Harness and Workbench runs default to the `rgb_proprio_calibrated_v1` profile with the `robodojo-calibrated-rgb-proprio-no-task-truth-v1` information policy. Under this policy, the actor can read exact camera intrinsics, extrinsics, hand-eye transforms, and the public robot model, and can use geometry and scene tools to compute estimates from permitted RGB observations and robot proprioception. Because this expands the available information compared to the legacy `rgb_proprio_v1` profile, results must not be mixed with `rgb_proprio_v1` scores or claimed to reproduce the official default observation protocol.

Passing `--observation-profile rgb_proprio_v1` retains the legacy `robodojo-rgb-proprio-no-privilege-v1` policy for explicit comparisons without camera calibration or calibration-derived tools. Existing frozen source trees, experiments, reports, and run archives are never rewritten. The official reference adapter for the simple API continues to select the legacy profile explicitly to preserve its declared upstream observation conditions.

The `rgbd_proprio_calibrated_v1` profile is a separate, opt-in condition that **does not alter the defaults above**. Only this profile permits native float32 metric z-depth artifact references bound to RGB and calibration; raw depth arrays never enter model responses. `depth_query`, `depth_move` (removed), and depth query aliases in geometry tools are all gated by this profile check. Three additional flags—`depth_auto_feedback`, `depth_skills`, and `depth_event_payload`—all default to `false` and cannot bypass the profile requirement. Standard RGB configurations actively disable depth capture after native task overrides are applied, and both historical observation reads and program artifact reads reject depth inputs and explicitly tagged depth-derived results. RGB-D does not expose hidden object poses, contact states, or scoring ground truth; see [RGB-D Numeric Tools and Bounded Manipulation Skills](rgbd-numeric-tools.md) for contracts and usage. The table below describes the two RGB profiles where depth remains disabled by default.

## Available Data

| Data | Default Calibrated Profile (`rgb_proprio_calibrated_v1`) | Legacy RGB / Proprio Profile (`rgb_proprio_v1`) |
|---|---|---|
| Raw RGB images, image dimensions, public task instruction, provenance-tagged crops | Available | Available |
| Arm joint angles, `link6` end-effector pose, executed actions, and gripper commands | Available | Available |
| Joint names, velocities, and measured finger positions | Available as part of robot proprioception | Not published; retains legacy projection |
| Public ARX X5 geometry, fixed grasp offset, and full kinematic model | Available | Only previously disclosed interface dimensions and offsets |
| Camera intrinsics `K`, distortion parameters, extrinsics, hand-eye transforms, per-frame camera poses | Available; bound to corresponding RGB, robot state, and provenance | Prohibited |
| Rays, projections, triangulation, and RGB-estimated scene geometry | Available; annotated with provenance, errors, assumptions, and degeneracy conditions | Prohibited |
| Hidden object poses, native depth, contact ground truth, undisclosed scoring thresholds, and evaluator state | Prohibited | Prohibited |
| Native USD pose diagnostics, private planning diagnostics, and observer snapshots | Prohibited | Prohibited |

Calibration describes the cameras and the robot; it does not provide ground-truth depth, identity, pose, mass, friction, or contact state for task objects. Triangulation still requires valid visible point correspondences and sufficient parallax, and scene estimates are never backfilled from hidden simulator state. Measured finger aperture, trajectory completion, or end-effector elevation alone does not prove that an object has been grasped. Public programs and skills must not hardcode hidden target coordinates for specific layouts, task recipes derived from hidden ground truth, or undisclosed scoring thresholds.

Benchmark task descriptions use the [Official Task Rules and Scoring Tables](public-task-rules.md): the official website's Instruction, Description, optional Comment, and Scoring sections are injected verbatim, including all publicly disclosed numeric thresholds and scoring conditions, without summarization, correction, or extra commentary. Static public instructions are distinct from live evaluator state; each run archives the exact text used, and resuming an older run never replaces it with a newer version.

## Tools and Execution

`robot_wait` is enabled by default; `--no-enable-wait` preserves an explicit no-wait control condition. By default, `--motion-review` enables motion preview, post-review plan execution, and grasp planning/memory tools. Passing `--no-motion-review` disables those tools while retaining the same camera calibration and geometry/scene tools for tool-intervention ablations. Selecting the legacy profile automatically disables all calibration-dependent tools. Previews do not advance the simulation; plans must still be executed through the single Harness action entrypoint. The scope of the collision model and the provenance of estimated obstacles must remain explicit; passing collision checks against the robot body and static table does not guarantee collision-free motion with respect to held objects, other scene objects, or the other arm.

Grasp memory persists to `~/.local/share/auriga/grasp-memory` by default and can be pointed to an isolated store via `features.grasp_memory_dir` in configuration or `--grasp-memory-dir` on the CLI (the repository default config sets this path, so the `AURIGA_GRASP_MEMORY_DIR` environment variable does not override it). Stored entries retain object category/instance descriptions, applicability conditions, and observation/action provenance rather than reusing raw coordinates from past scenes. Paired benchmark evaluations isolate read/write memory per episode via an absolute per-run `grasp_memory_dir` path in the queue to prevent cross-condition contamination.

The Gateway CLI, Workbench constructor, and benchmark queue all default to the calibrated profile and record the active profile, information policy, motion-review flag, and source hash in the run manifest. Resumed sessions only accept an information policy and profile matching the archive; legacy sessions lacking policy metadata cannot be upgraded in place and require a new run or thread. Offline replay can inspect the original archived evidence.

## Model-Facing Presentation

Model context carries only information needed for current decision-making. Build, provenance, and storage verification hashes are stripped before reaching the model; the primary actor model, auxiliary models, program responses, text artifacts, and resumed conversation histories all pass through the same filter. Necessary objects are addressed via reversible short references, while action statuses, key diagnostics, plan control revisions, and measured numeric values are preserved. This filtering applies regardless of `summary` vs. `full` detail selection—full queries never expose non-essential verification metadata. Internal typed structures and observer archives retain the original verification hashes.

Native Codex base instructions, tool catalogs, general programming capabilities, and file/memory tools are preserved; the default base prompt and native capabilities are never overridden or truncated to save context. The model is free to write helper scripts within its sandbox and permitted observation scope. Context reduction in the Harness operates strictly at its own producer and presentation boundaries: `StructuredText.projection` strips known record envelopes, and actor and program callers share pure metadata projection without applying actor evidence summarization to program responses. Geometry outputs omit algorithm implementation versions, dependency versions, and compute wall-clock times while retaining all measurements, diagnostics, uncertainties, and proposed geometric or control fields. Raw `ScenePatch` objects remain available to trusted scene owners, whereas model-facing copies strip verification hashes and cannot be resubmitted as raw protocol objects. Internal threads, turns, backend details, and context policies for visual review stay confined to observer records.

Keys in stage mappings represent domain labels and are preserved even if named `hash` or `sha256`, while verification metadata inside mapping values is stripped as usual. Clock domains carrying internal environment identifiers are mapped to stable, recoverable `clock_N` identifiers without merging distinct environments or generations, preserving step counts and timing precision. Action artifacts verify original permissions and provenance before projecting read copies according to their producer-declared kind. Unknown business records and legacy wire artifacts without a declared projection fall back to generic filtering rather than guessing field semantics from structure.

Task-decision reminders injected into primary model requests read only the current episode's actor-authored plan and attention list, presenting them as tentative assistant judgments rather than new task requirements or measured facts. Every actor request delivers the complete current plan, attention list, ledger, revision, and supporting observation references; because the upstream provider chain does not guarantee a reliable cross-request snapshot cache, brief reminders cannot substitute for the full state. At the request egress boundary, prior Harness snapshots are stripped before appending the latest snapshot; unknown threads, auxiliary visual models, and schema-only projections receive no injection. See [Unified Actions and Task Planning](unified-actions.md) for details.

New runs default to `--actor-payload-profile lean_v1`. This profile streamlines the routine action and observation JSON delivered to the model without altering observation permissions, image bytes, action execution, program interfaces, or underlying storage. It never rounds numeric values, truncates actual execution requests, or removes `step_semantics`, `trace_sampling`, errors, partial execution results, timing/synchronization metadata, or reconstruction warnings.

| Field Location | `lean_v1` Presentation |
|---|---|
| `versions` in action receipts | Omits build and dependency versions; retained in full in backend storage |
| Camera `image_encoding`, image view `encoding`, and sibling `sha256` / `source_sha256` | Omits storage encoding metadata; preserves images, effective dimensions, and pixel transforms |
| Receipt `planned_trace_ref`, `dispatched_trace_ref`, `actual_trace_ref`, `before_state_ref` | Replaced with corresponding `*_available` booleans; full contents remain readable via `history_read_trace(action_id, kind)` |
| `robot_state_ref` | Replaced with `robot_state_available` when the robot state is already expanded inline in the same response |
| Camera / crop view `rgb_ref` and crop view `original_rgb_ref` | Replaced with availability flags; preserves observation/camera IDs, crop parameters, and pixel transforms (images remain accessible via history observation tools) |
| `calibration_ref` / `pose_sample_ref` | Replaced with availability flags only when the corresponding content is already expanded inline in the same response and matches the expanded source; distinct references for other cameras are preserved |

Present references, explicit `null` values, and omitted fields map to `true`, `false`, and omitted fields, respectively. References with unrecognized formats or collisions with existing availability fields are preserved verbatim. Unrecognized fields and other references are never indiscriminately stripped; `robot_model_ref`, motion preview `trace_ref`, and similar handles remain readable by programs. On-demand calls to `robot_action_status` and `history_list_actions` return complete records.

`full_v1` preserves the uncondensed presentation, while `compact_v1` retains the field removal and six-decimal-place rounding used in historical experiments. The active profile is recorded in the manifest and honored on resume/replay, with older archives lacking the field defaulting back to `full_v1`. Payload-profile unit tests verify numeric fidelity and evidence retention, which does not by itself establish robot task performance or full-episode token savings.

In default runs with calibration enabled, the startup `robot_information` briefing delivers the episode's camera mount and base calibration, reporting any missing or permission-restricted fields under `available` / `unavailable_fields`. Routine observation summaries keep the current `camera_pose_sample.T_world_camera` while leaving static mount, base, and link reconstruction matrices in the full observation reference. Camera intrinsics, joint names, and coordinate conventions are deduplicated across the model context via `metadata_delivery.static_refs`: after the initial observation delivery, unchanged values are replaced by references and re-delivered only when values change, the environment resets, the context is compacted, or delivery state becomes uncertain. Program-internal reads never advance the delivery baseline for the primary actor model; live robot measurements, camera poses, and budgets continue to update with every observation. Per-frame `T_world_link` transforms remain accessible in full observations, as initial startup transforms cannot substitute for live motion measurements.

Default responses from `robot_contact_overlay` retain both the rendered overlay image and the complete numeric `points`, `arrows`, and `approach_arrow_length_m` fields. Pixel coordinates and camera-frame depths are computed by projecting robot reference points; when occlusion is not evaluated, the response explicitly retains `not_evaluated` and must never be interpreted as object depth, physical contact, or grasp ground truth.

## Other Execution Entrypoints

`configs/images.json` controls image encoding only; pricing files and `environment.yml` never override the observation profile or tool switches. The local experiment settings loader accepts only the Codex home directory and rate-card path, leaving profile, motion review, and wait settings to the Gateway CLI or per-episode queue configuration.

Fixed robot smoke tests, calibration checks, and native controller / pi0.5 handoff diagnostics use calibrated observations. Because they have no model review phase, they explicitly disable motion review and log their execution role; replaying fixed historical actions is never misrepresented as a model-reviewed plan. `ReferenceRecorder` acts as a passive recorder whose boundary is bound to the explicit profile in the backend capabilities at startup (defaulting to calibrated for generic new recordings without a declared profile, and disallowing mid-run profile changes once bound). If a caller specifies a profile explicitly, it must match the backend capabilities.

The official simple API adapter in `reference_episode.py` and the fixed upstream golden reference in `reference_baseline.py` continue to specify `rgb_proprio_v1` explicitly to preserve their declared reference input conditions. Existing frozen source trees, configurations, and resumed sessions retain their archived conditions and are logged separately from the calibrated mainline.

## Enforced Boundaries

- The robot worker outputs permitted calibration and proprioceptive state, and the Harness re-verifies the active profile, recursive forbidden-field rules, and state allowlists across initial, pre-action, progress, terminal, and historical observations. `before_state` and `actual_trace.state` are projected under the same profile rules.
- Actor-readable calibration and model artifacts must originate from verified public robot and camera specifications. `observer` artifacts cannot be read through `AurigaClient.artifact`. The `internal` label denotes data computed solely from permitted inputs and is never a backdoor for privileged diagnostics.
- When `features.sandbox_enabled=true` is explicitly enabled, the primary Codex agent, subagents, shell commands, and native memory run inside isolated mount, PID, IPC, and network namespaces. They have read-only access to a public Harness source copy and runtime dependencies, and read-write access to a private workspace; host filesystems, RoboDojo assets, evaluator state, observer data, and the full repository checkout are not mounted. Web search, host MCP servers/plugins, and arbitrary network access are disabled; package installation is restricted to a PyPI proxy, and authentication stays in the host relay. Native local tool search discovers only registered tools and cannot bypass role, availability, or execution checks. Model-authored programs executed via `program_run` remain constrained by pinned runtime dependencies, Landlock/seccomp policies, dedicated file descriptors, and artifact scopes; the evidence agent runs in its own isolated namespace with selected evidence only. See [Configuration Guide](configuration.md) for setup and migration details.
- `features.sandbox_enabled` defaults to `false`, which disables the primary/auxiliary Codex namespaces as well as Landlock/seccomp for programs. Tool projections, broker permissions, action auditing, and budgets remain enforced, but executed code inherits the launching user's host filesystem and network permissions. A private `HOME` / `CODEX_HOME` and placeholder credentials do not prevent reading other host paths, meaning formal observation boundaries are enforced at the application layer without OS-level isolation guarantees. Experiments must log this condition and must not be conflated with sandboxed runs.
- Native controller and motion-planning diagnostics are stored in observer-only paths and never enter prompts, tool results, or actor artifacts. Permitting accurate camera and robot calibration never unlocks native object, contact, or evaluator diagnostics.

Developers can still inspect scores, hidden state snapshots, and recordings via observer routes for offline forensics, documenting the source and timestamp in analysis reports. Insights from offline analysis may inform general-purpose tools and workflows, but layout-specific ground truth must never be hardcoded into production prompts or skills.

## Validation

`tests/test_observation_policy.py` covers state projection, nested privileged fields, historical profile isolation, and tool availability across profiles, while queue tests verify default and explicit control parameters. Geometry tool tests verify the input closure for calibration, projection, and triangulation. `tests/test_actor_isolation.py` verifies native primary Codex startup, in-sandbox file capabilities, and host filesystem/network rejection when the sandbox is enabled, as well as direct execution and resume constraints when disabled; program broker permissions and artifact boundaries are verified in both modes. `tests/test_codex_native_preferences.py` tests file reads and writes for the primary thread and memory consolidation using real native tools. These interface and boundary tests verify software isolation rather than robot task success rates.

By default, programs receive all saved text diagnostics and all action receipts without arbitrary character limits, recent-action sliding windows, or field allowlists that could drop decision-relevant evidence. Hashes and known non-functional metadata still pass through the shared projection, and duplicate logs are omitted only after confirmed delivery within the same context (and re-sent after compaction or reconnection). Privileged data blocked by the information boundary is never leaked through full output modes, and incomplete archives explicitly retain their incomplete markers.

Action phase names (such as `depth`) are interpreted as stage-mapping labels only when they match a verified action or an actual request stored in the Store; mapping values are still inspected recursively to block hidden depth, contact, or evaluator data. If privacy validation, serialization, or observation publishing fails after physical execution, the Harness preserves the verified minimal execution receipt and step count while invalidating stale observations—never automatically resending the physical action or rewriting missing stop confirmations or uncertain executions as successes.

Confirmed `stopped` states and observation checkpoints may proceed according to protocol. By contrast, `execution_uncertain=true` or an unconfirmed stop preserves its typed status, closes action admission, and maintains the evaluation block; capturing additional observations cannot lift this gate, which remains enforced when resuming receipts in the same environment.
