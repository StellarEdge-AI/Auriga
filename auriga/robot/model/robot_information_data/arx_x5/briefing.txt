ARX X5 physical reference

Scope: static physical knowledge for the installed Auriga/RoboDojo robot. This is not a live observation, manufacturer safety specification, or task solution. Runtime robot_capabilities, current measured proprioception and the current tool contracts take precedence. The original URDF is supplied inline, in metres, radians and kilograms; the compact reference adds interface and effective control parameters without duplicating its joint or inertial records. Native geometry files and current episode calibration are supplied directly; detailed physical records remain available through robot_information.

Your body consists of two independently controlled, fixed-base ARX X5A-derived arms. Each arm has six serial rotary joints, followed by a parallel two-finger gripper. The simulator models both fingers as separate prismatic joints, but a single normalized opening command drives them together. Thus the native bimanual policy action is 14 values: six joint angles plus one gripper command per arm. This does not make either arm a seven-rotary-joint redundant manipulator. Astra's normal motion tools request Cartesian end-effector/contact poses; the backend selects and executes joint trajectories.

The local base and link1–link6 shapes use X5A geometry; link7/link8 finger shapes are modified and wrist cameras are added. Other X5 variants have different parameters, and standard fingers do not match the modified local geometry. Some hardware variants also have conflicting limit specifications. The local physical model and configured driver settings describe this simulation.

Use the current RoboDojo episode calibration for the left/right base positions, orientations and separation. Assemble the two identical arm geometries with the supplied T_world_base transforms from the matching observed frame; missing calibration remains unavailable. Joint axes in their own local joint frames are J1:+Z, J2:+Y, J3:+Y, J4:+Y, J5:+Z, J6:+X. J3 and J6 have fixed approximately pi rotations about X in the URDF. Apply the parent-to-joint transform before joint motion; axis signs alone are not world directions. Main arm offsets include 264 mm between J2 and J3 and (245,0,-56) mm between J3 and J4. Those offsets do not define a spherical reachable workspace.

link6 is the Cartesian end-effector reference. The outward tool/approach axis is its local +X; the jaws separate along local ±Y. The default grasp reference is between the distal pads at +0.1501 m along link6 X. Grasp-target requests place the selected contact reference, and the harness performs the offset conversion. Do not add this offset a second time. pad_center, finger_middle and fingertip nominal offsets are 0.1501, 0.1226 and 0.1576 m respectively. The observation grasp_pose always uses pad_center. A reference between the fingers is a geometric point, not a report that an object is held. Named angles_deg use the harness's top-down reference, not absolute world Euler angles; API quaternions are xyzw while native configuration quaternions are wxyz.

Rotating the wrist moves the fingers and wrist camera through space. Even with the selected contact point fixed, the flange must translate to maintain its tool offset. Moving a target through a clear path does not establish that the elbow, wrist, camera, other arm or a held object clears surrounding geometry. A fixed full 6D pose does not generally leave a free elbow degree of freedom on this 6R arm. IK branches, joint limits and singular configurations affect feasibility. A failed local solve does not prove global unreachability; a successful plan does not prove physically completed motion or grasp retention.

Gripper command g is dimensionless: 0 requests closing, 1 requests opening. Native targets are qcmd7=qcmd8=-0.010+0.054*g metres, while authored URDF/USD joint bounds are 0..0.044 m. A requested target is not measured displacement, especially when the command is below the lower bound or an object blocks closure. For the modified distal flat pads, the rigid surface gap is approximately 0.000807166+q7+q8 metres using measured finger positions. At both joints zero that is about 0.807 mm; at both 0.044 m it is about 88.807 mm. This is geometric asset spacing, not a hardware opening rating, contact force or grasp-success signal. The finger interior includes a sloped shank and a distal flat 15 mm pad, so the same opening has different clearance at different insertion depths.

The default simulation configuration fixes the bases, enables self-collisions and disables gravity on the robot bodies. It uses implicit position drives: arm stiffness/damping 4400/40, effort limit 100, velocity limit 5 rad/s, armature 0.01; gripper stiffness/damping 2300/100 and effort limit 100. These are simulator configuration values, not certified hardware torque or gripping-force ratings. Disabling robot gravity is not a claim that objects lack gravity or that physical hardware is perfectly gravity compensated. The URDF's velocity=1000 and broad J1–J5 limits of ±10 rad must not be read as realistic hardware capability. J6 is declared ±3.14 rad. The URDF's declared mass sum is 3.454278 kg, excluding missing camera masses; it is not a measured product weight or payload.

The default timing configuration is a 0.004 s physics step and 25 Hz native actions (10 physics ticks per native action). Resampled arm commands normally limit each adjacent joint delta to 0.05 rad at scale 1, equivalent to a command-spacing bound of 1.25 rad/s; that is distinct from the 5 rad/s actuator setting and from actual velocity. Read current action_speed and measured q/qdot. Position-drive tracking can lag or stall under constraints; speed presets change command timing and do not guarantee physical speed. Static observations and wall-clock reasoning do not advance the paused simulation; actions and supported robot_wait do.

Visual meshes, PhysX collision approximations and planning geometry differ. The USD generally uses convex hulls (link3 uses convex decomposition); wrist cameras also have collision geometry. The planner uses collision spheres, and the harness adds finger bounds. These are finite approximations; sampled previews do not establish continuous clearance or contact. The preview implementation also maps future gripper commands with 0.044*g, unlike the native mapping above; use measured finger positions for current opening, and treat forecast finger clearance as approximate.

After motion, use actual robot state and fresh permitted visual evidence to distinguish requested, planned, commanded and achieved motion; distinguish empty closure, contact, a retained grasp and release. No reliable payload rating, force/torque curve, friction model, backlash, compliance, repeatability or experimentally validated stopping response is established by this reference. Episode home means the recorded initial measured state, not necessarily the all-zero default spawn pose.
